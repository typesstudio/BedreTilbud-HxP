1. Best workflow / where to paste what

When you want Replit AI to rebuild a page to match a Subframe design and reuse existing components, this is the workflow that tends to work best:

Open the exact page file you want to change
E.g. whatever file renders /sundhedstjek/:snapshotId
(likely something like client/src/pages/sundhedstjek.tsx or [snapshotId].tsx).

Run Subframe sync once in the Replit shell

npx @subframe/cli@latest sync --all -p 34bd735365b5


In the Replit AI chat (while that file is open), send ONE structured prompt with:

Context section

What this page does (/sundhedstjek/:snapshotId, uses usePolicyHealthCheck etc.)

Which components it should reuse from client/src/components/comparison/*
(summary cards, highlights, coverage matrix, savings chart).

Design section

Paste the Subframe TSX snippet for the health-check layout.

Mention that the attached screenshot shows the visual target.

Data mapping section

Explain which fields from the health-check hook should go where
(company name, premium, coverages, “hvad er inkluderet”, etc.).

Constraints / success criteria

No static numbers or hardcoded text where data exists.

Reuse existing comparison components where possible.

Don’t break the route or API calls.

Attach the screenshot in Replit
When you talk to Replit AI, attach the “Indbo sundhedstjek” screenshot and say “use this as visual reference”.

So yes: Subframe TSX + screenshot + clear data mapping all go into the same Replit prompt, while the health-check page file is open.
