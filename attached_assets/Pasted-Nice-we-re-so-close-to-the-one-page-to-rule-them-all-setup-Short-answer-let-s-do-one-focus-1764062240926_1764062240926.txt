## Replit prompt – make per-category comparison using shared components

> You are working in the BedreTilbud repo.
> The goal is to extend the comparison page so that:
>
> * The **Samlet** tab shows the aggregated comparison (already working).
> * The **Indbo / Hus / Ulykke / Bil / Rejse** tabs show **per-category** comparisons.
> * All sections **reuse the same shared components** as Samlet:
>
>   * `ComparisonSummaryCards` (3 top cards)
>   * `ComparisonQuickTable` (Hurtig sammenligning)
>   * `ComparisonHighlights` (Højdepunkter hvor anbefalingen er bedre)
>   * `ComparisonDetailedMatrix` (Detaljeret sammenligning)
>   * `ComparisonSavingsChart` (Din besparelse over tid)
> * There is **no duplicated JSX** for any of these sections – only the data changes.
> * All data is **dynamic** (no hard-coded numbers).

### 1. Inspect current comparison view model + components

1. Open `client/src/utils/transformComparison.ts` and find the **main transformer** that turns `company_comparisons.comparison_json` into a view model for the page (often called something like `transformCompanyComparisonToViewModel` or similar).
2. Open the comparison page: `client/src/pages/comparison.tsx`.

   * It already uses the new shared components (summary cards, quick table, highlights, detailed matrix, savings chart) for the **Samlet** view.
3. Open the shared comparison components:

   * `client/src/components/comparison/ComparisonSummaryCards.tsx` (or similar)
   * `client/src/components/comparison/ComparisonQuickTable.tsx` (or wherever the “Hurtig sammenligning” table lives)
   * `client/src/components/comparison/ComparisonHighlights.tsx`
   * `client/src/components/comparison/ComparisonDetailedMatrix.tsx`
   * `client/src/components/comparison/ComparisonSavingsChart.tsx`

Do **not** change their visual structure; we only want to adjust props and data.

### 2. Extend the view model with per-tab views

Update `transformComparison.ts` so the **returned view model** has a clear structure for **tabs**:

```ts
// Example shape – adapt to existing naming, don’t break other code
export type ComparisonTabKey = "samlet" | "indbo" | "hus" | "ulykke" | "bil" | "rejse";

export interface ComparisonTabView {
  key: ComparisonTabKey;
  label: string;            // "Samlet", "Indbo", "Hus", ...
  policyType: string | null; // e.g. "indbo" | "hus" | "ulykke" | null for samlet
  isAvailable: boolean;     // false if there is no such policy in policyComparisons

  // data for components:
  summary: {
    annualSavings: number;          // total savings for this tab
    totalCurrentAnnual: number;
    totalOfferAnnual: number;
    savingsPct: number;             // 0–100
  };

  quickRows: QuickRowView[];        // for the Hurtig sammenligning table
  highlights: HighlightView[];      // Højdepunkter
  coverageRows: ComparisonCoverageRowView[]; // for ComparisonDetailedMatrix

  savingsChart: {
    categories: string[];           // series labels, e.g. ["Hus", "Indbo", "Ulykke"] or ["Indbo"]
    data: SavingsPoint[];           // already used by ComparisonSavingsChart
    summary: SavingsSummary;        // monthlyMin, monthlyMax, year1Total, year10Total
    total10YearAll: number;         // used in the top-right badge
  };
}

export interface CompanyComparisonViewModel {
  // existing fields (comparisonId, offerCompanyName, currentCompanyName, etc.)
  tabs: Record<ComparisonTabKey, ComparisonTabView>;
  defaultTab: ComparisonTabKey; // usually "samlet"
}
```

Implementation notes:

* **Samlet tab**

  * Use the **existing aggregated data** you already calculate (total savings, total current, total offer, combined quick rows, combined highlights, combined coverage rows, multi-series savings chart).
* **Per-policy tabs (indbo, hus, ulykke, bil, rejse)**

  * For each `policyComparisons` entry in `comparison_json.policyComparisons`, build a matching `ComparisonTabView` using **only that policy’s data**:

    * `summary` uses that policy’s `currentAnnual`, `offerAnnual`, and `annualSavings`.
    * `quickRows` contains **one row** (that policy).
    * `highlights` and `coverageRows` come directly from that policy’s comparison data.
    * `savingsChart`:

      * `categories = [label]` (e.g. `["Hus"]`).
      * `data` is the monthly chart for that one policy (you can reuse the same helper you used to generate the multi-series chart, but only for one policy).
      * `summary` and `total10YearAll` are calculated for that policy only.
  * If a policy type doesn’t exist (e.g. no Bil), create a `ComparisonTabView` with `isAvailable = false` and **empty arrays** for `quickRows`, `highlights`, `coverageRows`, and a savingsChart with zeros. This allows the UI to show “Afventer” state like before.

Make sure **Samlet** is still fully populated and **existing consumers of the transformer** keep working.

### 3. Wire up tab switching in `comparison.tsx`

In `client/src/pages/comparison.tsx`:

1. Import the `ComparisonTabKey` type (or re-declare a compatible union type in this file).
2. After you load the comparison view model via your hook (e.g. `useCompanyComparison`), add React state for the active tab:

```tsx
const [activeTab, setActiveTab] = useState<ComparisonTabKey>(
  view.tabs.samlet ? "samlet" : view.defaultTab
);

const activeView = view.tabs[activeTab] ?? view.tabs[view.defaultTab];
```

3. In the Subframe `ListingsTabs` component at the top of the page, wire each tab to this state:

4. Everywhere the page currently renders data for Samlet, change it to use **`activeView`** instead:

```tsx

```

* “Hurtig sammenligning” table:

5. **Unavailable tabs** (e.g. no Bil / Rejse):

   * If `activeView.isAvailable === false`, still show the top header & cards (all zero), but:

     * Let the savings chart show a flat zero line using the empty `savingsChart` from the transformer.
