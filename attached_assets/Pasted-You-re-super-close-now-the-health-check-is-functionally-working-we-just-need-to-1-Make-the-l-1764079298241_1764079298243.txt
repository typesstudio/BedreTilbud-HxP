## 1. Implementation plan (what should happen)

### A. Reuse comparison components for health check

On the frontend we want this structure:

* **Shared / reused components**

  * `ComparisonHeader` – already used on `/sammenligning`.
  * `ComparisonHighlights` – the “Højdepunkter hvor anbefalingen er bedre” grid.
  * `ComparisonDetailedMatrix` – the coverage table (we already built this).
  * `ComparisonSavingsChart` – the chart + “Månedlig besparelse / 12 mdr / 10 år” cards.
* **New health-check specific components**

  * `HealthCheckTabs` – top tabs (Indbo, Ulykke, Hus, Bil, Rejse) – but this can actually be the same Subframe `ListingsTabs` pattern we use in comparison.
  * `HealthCheckAnnualPotentialCard` – big “Årlig potentiel besparelse” card.
  * `HealthCheckBenefitsGrid` – “Dine forsikringsfordele” (4 cards row).
  * `HealthCheckStrengthsWeaknesses` – “Styrker & svagheder” two-column grid.

The **health-check page** then becomes mostly composition:

```tsx
<DefaultPageLayout>
  <ComparisonHeader ... />           // same header as comparison
  <HealthCheckTabs ... />           // same icon tabs as comparison, but for health checks
  <HealthCheckAnnualPotentialCard ... />
  <HealthCheckBenefitsGrid ... />
  <ComparisonDetailedMatrix ... />  // reused, but single column for the offer
  <HealthCheckStrengthsWeaknesses ... />
  <ComparisonSavingsChart ... />    // reused, but fed with single-policy savings series
  <FooterCTA ... />                 // “Choose and switch to Tryg”
</DefaultPageLayout>
```

### B. Data wiring

Use the **existing view model** from `client/src/utils/transformHealthCheck.ts` as the single source of truth.

Rough mapping (names may be slightly different in your code – Replit should “follow the type”):

* `healthCheck.overall.annualPotentialSavings` → “Årlig potentiel besparelse”
* `healthCheck.overall.annualSavingsPercent` → `Din årlige besparelse 20.5% lavere omkostning`
* `healthCheck.policy`:

  * `companyName`
  * `policyType` (“Indbo”, “Hus”, etc.)
  * `annualPremium`
* `healthCheck.benefits[]` → “Dine forsikringsfordele” cards
* `healthCheck.coverages[]` → “Hvad er inkluderet” rows
* `healthCheck.strengths[]` & `healthCheck.weaknesses[]` → “Styrker & svagheder”
* `healthCheck.savingsOverTime` (or similar) → data for `ComparisonSavingsChart`:

  * `chartPoints: { monthIndex, cumulativeSaving }[]`
  * `monthlySavingsRange` / `totalAfter12Months` / `totalAfter10Years`

If some fields don’t exist, they should be **computed in `transformHealthCheck.ts`**, not hard-coded in the component.

### C. Tabs + navigation

* The **tabs row** on the health-check page (Indbo/Ulykke/Hus/Bil/Rejse) should reuse the same `ListingsTabs` component as the comparison page.
* When you click a tab:

  * It should navigate to the same `/sundhedstjek/:snapshotId` page but with the snapshot for that policy type (or at least visually update selection; navigation details can follow the pattern you already use for comparison tabs).
