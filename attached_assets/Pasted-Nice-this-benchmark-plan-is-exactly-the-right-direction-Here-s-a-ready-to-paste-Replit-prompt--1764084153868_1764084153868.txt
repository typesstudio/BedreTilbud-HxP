````text
## PHASE 2 – BACKEND LOGIC: health check service
##################################################

Goal: extend the health-check generation logic so it uses benchmarks when there’s no current policy price.

1. Find the health-check service/orchestrator:

   - e.g. `server/services/healthCheckService.ts` (or similarly named).

2. Identify where “savings” and “cumulative savings” are currently calculated for a health check.

3. Implement the following logic in a clearly named helper function, e.g. `computeBenchmarkSavings(policyType, maybeCurrentPremium, offerAnnualPremium)`:

   - Input:
     - `policyType: string`
     - `currentPremium: number | null` (can be null/undefined if user has no current policy price)
     - `offerPremium: number` (required)

   - Logic:
     - If `currentPremium` exists and is > 0:
       - Use that as the baseline (this is the “normal” case – keep existing behaviour).
     - ELSE:
       - Call `getBenchmarkPrice(policyType)` from `server/storage.ts`.
       - If benchmark exists → use that as the baseline.
       - If no benchmark exists → do NOT crash; set savings to 0 and mark percentage as 0.

     - Let `baseline = currentPremium ?? benchmark`.
     - Compute:
       - `savingsAnnual = baseline - offerPremium` (can be negative).
       - `savingsPercent = baseline > 0 ? (savingsAnnual / baseline) * 100 : 0`.

     - Generate cumulative projections for the health-check JSON:
       - Monthly savings ≈ `savingsAnnual / 12`.
       - 12-month total = `savingsAnnual`.
       - 10-year projection = `savingsAnnual * 10`. (Keep it simple and deterministic.)

       Also build a simple time-series array for the chart for 120 months:
       - index 0..119 → each month.
       - cumulativeSavings = monthIndex * (savingsAnnual / 12).
       - The existing chart transform should be able to read this.

   Inside the health-check object (check existing schema/typing, but conceptually):

   ```ts
   {
     ...,

       annualPotentialSavings: number;      // kr value (baseline - offer)
       annualSavingsPercent: number;        // percentage (e.g. 20.5)
       baselineAnnualPremium: number;       // either current premium or benchmark
       offerAnnualPremium: number;

       // cumulative
       monthlySavings: number;
       twelveMonthSavings: number;
       tenYearSavings: number;
     },
     savingsOverTime: {
       points: Array<{ monthIndex: number; cumulativeSavings: number }>;
     }
````

Adjust field names to match **existing client expectations** if there is already a structure in `transformHealthCheck.ts`. Prefer changing the server to match existing client names rather than the opposite, unless there is no prior contract.
