### 3.4 Step C – Health check consistency

Query `health_checks` for this user:

- JOIN offer_snapshots ON health_checks.snapshot_id = offer_snapshots.id
- JOIN documents ON offer_snapshots.document_id = documents.id
- LEFT JOIN companies ON offer_snapshots.company_id = companies.id

For each health check:

1. Extract:
   - snapshot_id
   - doc_type (current/offer)
   - company_name
   - policy_type (from snapshot)
   - result.whatsIncluded (array)

2. Implement a small helper `guessPolicyTypeFromCoverages(whatsIncluded)`:

   - If most coverage names look like:
     - "Brand", "Bygningsbrand", "Bygningsbeskadigelse", "Råd, svamp", "Stikledninger" → guess "hus"
     - "Indbo", "Cykel", "Ansvar", "ID-tyveri" → guess "indbo"

   - If unclear, return "ukendt".

3. For each row, log:

   - `[HEALTH] snapshot=<id> doc_type=<current|offer> company=<name> policy_type(db)=<hus/indbo/ulykke> policy_type(guessed)=<hus/indbo/ulykke/ukendt> whatsIncludedCount=<n> firstCoverages=[...first 3 names...]`

4. If `guessedType !== snapshot.policy_type`, log a warning:

This should clearly show the current bug where:
- current_hus_health_check actually looks like “ulykke”
- offer_ulykke_health_check looks like “indbo”
