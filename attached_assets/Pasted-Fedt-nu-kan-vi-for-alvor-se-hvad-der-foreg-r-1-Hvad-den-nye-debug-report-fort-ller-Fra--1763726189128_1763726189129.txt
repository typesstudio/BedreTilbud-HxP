## 2. Hvad vi skal ændre i backenden

Høj-niveau:

1. **Aldrig brug 0 som “ukendt pris”**

   * Hvis vi ikke har pris → `null`, ikke `0`.
2. **Per policy:**

   * `currentAnnualPremium` og `offerAnnualPremium` skal være `number | null`.
   * `annualSavings` og `annualSavingsPercent` skal kun beregnes, hvis **begge** sider har tal.
3. **Overall totals:**

   * `totalCurrentAnnualPremium` og `totalOfferAnnualPremium` skal kun summere policies, hvor begge sider har pris.
   * Hvis kun 1/3 policies har pris (som i Gjensidige-casen), skal overall kun reflektere den ene – ikke de 2 ukendte.

Det gør din visning ærlig:
– Du kan stadig vise full coverage-comparison for hus/indbo, men tydeligt markere, at pris/savings er baseret på delvis pris-info.

## Step 2 – Introduce a safe helper for annual premium

Create a small helper function in the same module as the cost summary builder, for example:

```ts
function getAnnualPremiumFromSnapshot(
  snapshot: OfferSnapshot | null | undefined
): number | null {
  if (!snapshot) return null;

  const structured = snapshot.structuredPolicy as any | null | undefined;
  const fromSnapshot = snapshot.premium ?? null;
  const fromStructured =
    typeof structured?.annualPremium === 'number'
      ? structured.annualPremium
      : null;

  // Prefer explicit snapshot.premium if present, otherwise structured annualPremium
  const value = fromSnapshot ?? fromStructured;

  if (value == null) return null;

  // Treat 0 as "unknown" – we never want 0 DKK as a default
  if (value === 0) return null;

  return value;
}
```

Adjust the type names (`OfferSnapshot`, field names etc.) to match the actual codebase.

Then, in the policy builder, replace any previous logic like:

```ts
const currentAnnual = snapshotCurrent.premium ?? 0;
const offerAnnual = snapshotOffer.premium ?? 0;
// or
const currentAnnual = structuredCurrent?.annualPremium || 0;
```

with:

```ts
const currentAnnual = getAnnualPremiumFromSnapshot(currentSnapshot);
const offerAnnual = getAnnualPremiumFromSnapshot(offerSnapshot);
```

Update the `costSummary` type so that `currentAnnualPremium` and `offerAnnualPremium` are `number | null`.

## Step 4 – Fix the overall totals

Find where the top-level `overall` block is built, something like:

```ts
overall: {
  totalCurrentAnnualPremium,
  totalOfferAnnualPremium,
  annualSavings,
  annualSavingsPercent,
  ...
}
```

This is usually computed from the array of per-policy summaries.

Change the logic to:

```ts
const pricedPolicies = policyComparisons.filter(pc =>
  pc.costSummary.currentAnnualPremium != null &&
  pc.costSummary.offerAnnualPremium != null
);

let totalCurrentAnnualPremium: number | null = null;
let totalOfferAnnualPremium: number | null = null;
let overallAnnualSavings: number | null = null;
let overallAnnualSavingsPercent: number | null = null;

if (pricedPolicies.length > 0) {
  const sumCurrent = pricedPolicies.reduce(
    (sum, pc) => sum + (pc.costSummary.currentAnnualPremium as number),
    0
  );
  const sumOffer = pricedPolicies.reduce(
    (sum, pc) => sum + (pc.costSummary.offerAnnualPremium as number),
    0
  );

  totalCurrentAnnualPremium = sumCurrent;
  totalOfferAnnualPremium = sumOffer;

  overallAnnualSavings = sumCurrent - sumOffer;
  overallAnnualSavingsPercent =
    sumCurrent > 0 ? (overallAnnualSavings / sumCurrent) * 100 : null;
}
```

Then write these values into the `overall` section of the comparison JSON.

Optionally, also add a small meta field:

```ts
pricingCoverage: {
  pricedPolicies: pricedPolicies.length,
  totalPolicies: policyComparisons.length,
}
```

but this is optional for now.
