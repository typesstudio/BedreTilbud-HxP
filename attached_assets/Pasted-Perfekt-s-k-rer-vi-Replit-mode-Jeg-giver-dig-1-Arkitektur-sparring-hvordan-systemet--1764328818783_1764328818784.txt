## 1. Arkitektur – hvordan det bør fungere

Mål:
Når et selskab svarer med noget a la:

> “For at se tilbuddet skal kunden logge ind med MitID / gå på selvbetjening / Min Side.”

**og der ikke er nogen PDF vedhæftet**,
så skal systemet **automatisk svare**:

* Tak for mailen
* Vi arbejder på vegne af kunden
* Vi kan ikke nøjes med MitID/link
* De skal sende **det konkrete tilbud som PDF vedhæftet denne mail**

### Bedste system-setup

**Flow for indgående mails:**

1. IMAP/webhook → vi får en `incomingEmail` (body + attachments + company + thread osv.).

2. Vi kører en central funktion, fx:

   ```ts
   const mode = classifyIncomingEmailForAutoResponse(incomingEmail);
   ```

3. `mode` kan være:

   * `"none"` – svar ikke automatisk
   * `"normal"` – brug almindelig auto-response (fx opklarende spørgsmål)
   * `"mitid"` – special-case: MitID/selvbetjening uden PDF → **send “send PDF-tilbud” svar**

4. Hvis `mode === "mitid"`:

   * Kald `generateResponse({ ..., responseMode: "mitid" })`
   * Send mailen tilbage via `emailService.sendEmail(...)`.

**Fordele ved denne struktur:**

* Du har **én samlet klassifikation**, som du senere kan udvide (fx “offer_with_pdf”, “complaint”, “legal_risk” osv.).
* Du kan logge `mode` i databasen, hvis du vil analysere, hvilke selskaber spammer med MitID-links.
* Du holder prompts rene:
  – logikken (MitID-detektion) ligger i kode,
  – formuleringen (“send PDF i denne mail”) ligger i prompten.

Step 1 – Find the incoming email handling flow
1. Search the repo for where incoming emails are processed (IMAP/webhook handler).

     - parses incoming emails
     - calls aiResponseService.generateResponse (or similar)

2. Identify the function that decides whether to auto-respond or not.

Step 2 – Introduce a classifier with a special "mitid" mode
In server/services/aiResponseService.ts (or the most appropriate place), implement:

- A helper function:

  ```ts
  function isMitIdOnlyEmail(body: string): boolean {
    const lower = body.toLowerCase();

    const patterns = [
      'mitid',
      'mit id',
      'log ind med mitid',
      'log på med mitid',
      'gå ind på mitid',
      'selvbetjening',
      'selvbetjeningen',
      'min side',
      'minside',
      'kundeportal',
    ];

    return patterns.some((p) => lower.includes(p));
  }
````

* A classifier function that returns a mode:

  ```ts
  export type AutoRespondMode = 'none' | 'normal' | 'mitid';

  export function classifyIncomingEmailForAutoResponse(email: {
    body: string;
    attachments?: { mimeType?: string; contentType?: string }[];
  }): AutoRespondMode {
    const body = email.body ?? '';
    const attachments = email.attachments ?? [];

    const hasPdfAttachment = attachments.some((a) => {
      const type = (a.mimeType || a.contentType || '').toLowerCase();
      return type.includes('pdf');
    });

    // 1) MitID / self-service mail without PDF => always auto-respond in "mitid" mode
    if (isMitIdOnlyEmail(body) && !hasPdfAttachment) {
      return 'mitid';
    }

    // 2) If there is a PDF offer attached, we generally do NOT auto-respond by default.
    //    (You can tweak this logic later if you want.)
    if (hasPdfAttachment) {
      return 'none';
    }

    // 3) Filter out spam/system mails
    if (/noreply|no-reply|do not reply|unsubscribe/i.test(body)) {
      return 'none';
    }

    // 4) Very short messages -> no auto-response
    if (body.trim().length < 20) {
      return 'none';
    }

    // 5) Default -> normal auto-response mode for "ordinary" emails
    return 'normal';
  }
  ```

Adjust the parameter shape if your email object is typed differently (e.g. ParsedEmail).

Step 3 – Wire the classifier into the incoming email flow
In the file where incoming company emails are handled (IMAP/webhook handler):

1. After parsing the incoming email into an object with body + attachments, call:

   ```ts

     body: incomingEmail.body,

   });
   ```

2. If mode is 'none', do nothing (no auto-reply):

   ```ts

     return;

   ```

3. For mode === 'mitid':

   * Call aiResponseService.generateResponse with an extra hint/parameter telling the model that this is a MitID-only case.

   Example (adapt to your function signature):

   ```ts
   const replyBody = await aiResponseService.generateResponse({
     incomingEmailBody: incomingEmail.body,
     companyName,
     sentEmail: originalOutgoingEmailBody,

   await emailService.sendEmail({
     to: companyEmail,
     subject: incomingEmail.subject ?? `Vedr. jeres tilbud`,
     body: replyBody,
     threadId: incomingEmail.threadId, // or whatever your threading identifier is
   });
   ```

4. For mode === 'normal':

   * Keep your existing behavior (whatever you already do for generic auto-responses), but consider passing `responseMode: 'normal'` so the prompt can adjust slightly if needed.
