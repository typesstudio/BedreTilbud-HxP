Current Behavior / Problems

1) **Offers exist but don’t show in the UI**
   - New offers (e.g. IF Forsikring / Tryg) are uploaded correctly:
     - `documents.document_type = 'offer'`
     - Snapshots + health checks exist.
   - The **offers overview page** does NOT list raw offer documents.
   - Instead, it:
     - Calls `/api/comparisons/user/:userId`
     - Builds `companiesWithOffers` from **comparison results**.
   - For the new offers, all attempted comparisons currently fail because:
     - Current policies lack usable matching metadata (`structured_policy` is NULL or missing).
   - Result: Offers with failed comparisons are completely invisible in the UI.
   - This is a UX gap: uploaded offers that can’t be compared yet are not visible anywhere.

2) **Architectural issues confirmed by expert & debug session**
   - These are already analyzed and agreed to be correct:

   a) Health checks are linked only by `documentId` and matched by **array index**:
      - Code pattern:
        ```ts
        for (let i = 0; i < snapshots.length; i++) {
          const snapshot = snapshots[i];
          const healthCheck = uniqueHealthChecks[i];
          if (!healthCheck) {
            console.warn(`No health check for snapshot ${snapshot.id}, skipping`);
            continue;
          }
          // ...
        }
        ```
      - If there are 3 snapshots and 2 health checks, one snapshot (often the important one, e.g. a `hus` policy with valid `structured_policy`) gets dropped.
      - Health checks should instead be linked explicitly to the relevant snapshot.

   b) Queries used in matching have **no explicit ORDER BY**:
      - Example:
        ```ts
        async getOfferSnapshotsByDocument(documentId: string): Promise<OfferSnapshot[]> {
          return db
            .select()
            .from(offerSnapshots)
            .where(eq(offerSnapshots.documentId, documentId));
          // No .orderBy(...)
        }
        ```
      - Combined with index-based matching, this makes snapshot ↔ health check pairing nondeterministic.

   c) Legacy data limitation:
      - Current policies uploaded **before** the `structured_policy` fix have `structured_policy = NULL`.
      - New offers have proper `structured_policy` and can be matched, but the old current policies cannot participate in deterministic matching until re-uploaded or re-processed.
