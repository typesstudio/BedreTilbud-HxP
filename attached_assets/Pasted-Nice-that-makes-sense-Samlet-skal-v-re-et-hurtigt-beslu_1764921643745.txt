## Step 3 – Create OverallProsConsSection component

Create a new component for the Samlet view, e.g.:

`client/src/components/comparison/OverallProsConsSection.tsx`

This component should:

1. Accept the full comparison result:

   ```ts
   interface OverallProsConsSectionProps {
     comparison: ComparisonResult; // use the actual type used in comparison.tsx
   }
   ```

2. Derive **strengths** and **weaknesses** based on the comparison data.

   The intention is:

   * Strengths (pros) = things that speak FOR switching to the new company.
   * Weaknesses (cons) = things that speak AGAINST switching (or reasons to stay).

   Use deterministic rules from the existing data – do NOT call any LLM.

   Suggested logic (adapt to the actual shape):

   * Assume something like:

     ```ts
     comparison.companyName           // e.g. "Tryg", "Types Studio"
     comparison.currentCompanyName    // e.g. "Privatsikring"
     comparison.totalAnnualSavings    // number (can be negative)
     comparison.policyComparisons: PolicyComparison[] // one per policy type
     ```

   * For each `policyComparison`:

     ```ts
     type PolicyComparison = {
       policyType: string;
       annualSavings: number; // positive = offer cheaper, negative = offer more expensive
       betterCoverages?: CoverageHighlight[]; // offer better than current
       worseCoverages?: CoverageHighlight[];  // offer worse than current
       // or similar fields - inspect the actual type used in the comparison JSON
     };
     ```

   * Build two string arrays:

     ```ts
     const strengths: string[] = [];
     const weaknesses: string[] = [];
     ```

     a) Price points:

     * If `comparison.totalAnnualSavings > 0`:

       ```ts
       strengths.push(
         `Du sparer ca. ${formatCurrency(comparison.totalAnnualSavings)} om året i alt ved at skifte.`
       );
       ```

     * If `comparison.totalAnnualSavings < 0`:

       ```ts
       weaknesses.push(
         `${comparison.companyName}-tilbuddet er ca. ${formatCurrency(Math.abs(comparison.totalAnnualSavings))} dyrere om året samlet set.`
       );
       ```

     * For each `policyComparison`:

       * If `annualSavings > 0`:

         ```ts
         strengths.push(
           `Billigere ${getPolicyTypeLabel(policyType)}: du sparer ca. ${formatCurrency(annualSavings)} om året.`
         );
         ```
       * If `annualSavings < 0`:

         ```ts
         weaknesses.push(
           `Dyrere ${getPolicyTypeLabel(policyType)}: ca. ${formatCurrency(Math.abs(annualSavings))} mere om året.`
         );
         ```

     b) Coverage improvements/downgrades:

     * Inspect the existing comparison data structure used for the detailed table.
       There is likely information about which coverage rows are “offer better” vs “offer worse” (for example with flags or `status` values).

       If you find arrays like `betterCoverages` / `worseCoverages` on each `policyComparison`, use them:

       ```ts
       policyComparison.betterCoverages?.slice(0, 3).forEach((c) => {
         strengths.push(
           `Bedre dækning på ${c.label} i ${getPolicyTypeLabel(policyType)} (${c.currentValue} → ${c.offerValue}).`
         );
       });

       policyComparison.worseCoverages?.slice(0, 3).forEach((c) => {
         weaknesses.push(
           `Lavere dækning på ${c.label} i ${getPolicyTypeLabel(policyType)} (${c.currentValue} → ${c.offerValue}).`
         );
       });
       ```

       If there is no explicit `betterCoverages`/`worseCoverages` array, derive them from the same data the detailed table uses (e.g. filtering coverage rows by a status/flag that indicates better/worse coverage).

   * Keep the list fairly short and readable:

     * After building the arrays, you can limit to e.g. max 6 items each:

       ```ts
       const strengthsToShow = strengths.slice(0, 6);
       const weaknessesToShow = weaknesses.slice(0, 6);
       ```

   * If one of the lists is empty, show a friendly fallback like:

     * For strengths: `"Ingen klare forbedringer i forhold til din nuværende dækning."`
     * For weaknesses: `"Ingen tydelige svagheder i forhold til din nuværende dækning."`

3. Render layout:

   * Title: `"Styrker og svagheder ved tilbuddet"`
   * Short subtitle referencing both companies:

     ```tsx
     <p>
       Sammenligning mellem {comparison.companyName} og {comparison.currentCompanyName}.
     </p>
     ```
   * Two side-by-side cards/columns on desktop, stacked on mobile:

   ```tsx
   <section className="mt-8 space-y-4">
     <div className="flex flex-col gap-4 md:flex-row">
       <div className="flex-1 rounded-2xl border bg-white p-4 md:p-6">
         <h3 className="text-sm font-semibold text-green-700">
           Styrker ved {comparison.companyName}-tilbuddet
         </h3>
         <ul className="mt-3 space-y-2 text-sm">
           {strengthsToShow.map((item, i) => (
             <li key={i} className="flex gap-2">
               <span className="mt-1 h-1.5 w-1.5 rounded-full bg-green-600" />
               <span>{item}</span>
             </li>
           ))}
           {strengthsToShow.length === 0 && (
             <li className="text-sm text-slate-500">
               Ingen klare forbedringer i forhold til din nuværende dækning.
             </li>
           )}
         </ul>
       </div>

       <div className="flex-1 rounded-2xl border bg-white p-4 md:p-6">
         <h3 className="text-sm font-semibold text-red-700">
           Svagheder ved {comparison.companyName}-tilbuddet
         </h3>
         <ul className="mt-3 space-y-2 text-sm">
           {weaknessesToShow.map((item, i) => (
             <li key={i} className="flex gap-2">
               <span className="mt-1 h-1.5 w-1.5 rounded-full bg-red-600" />
               <span>{item}</span>
             </li>
           ))}
           {weaknessesToShow.length === 0 && (
             <li className="text-sm text-slate-500">
               Ingen tydelige svagheder i forhold til din nuværende dækning.
             </li>
           )}
         </ul>
       </div>
     </div>
   </section>
   ```

   * Reuse existing typography/spacing utilities from the project so it fits the current design system (Inter, rounded cards, etc.).
