# Agent instructions

## Communication — learning and agent briefs (Philip, 2026-11-17)

- **To Philip:** use plain Danish by default, a few sentences or 3-5 short bullets. Lead with the result or decision. Define unfamiliar terms briefly.
- **Teach through the task:** explain the problem and mechanism, relevant options/trade-offs, your recommendation and a practical check. Use a small example when helpful; expand on request or for a material decision, not as a mandatory report in every update.
- **Make claims assessable:** distinguish verified facts, hypotheses and unknowns. Link relevant code/evidence; say what would confirm or disprove an important explanation and what remains untested.
- **Use the project's domain:** connect implementation to observable behaviour (in audio: signal flow and what Philip hears). Help him guide the work creatively and solve problems independently.
- **To agents:** use compact technical briefs in the worker's working language (English by default): goal, relevant context, exact paths/ownership, base revision, constraints, acceptance/check commands and expected result format. Preserve necessary detail; omit teaching prose, filler and full chat copies.
- **Worker results:** concise status, changes/commit, checks and actual results, blockers and uncertainties. Never fabricate evidence. The lead translates findings into useful explanations for Philip.
- This communication preference changes neither project scope nor safety/acceptance rules. Continue authorized work without compulsory quizzes or extra approval steps.
